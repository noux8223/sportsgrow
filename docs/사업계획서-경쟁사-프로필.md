### 0-3. 이 표를 읽는 3가지 방법

| 규칙 | 의미 | 근거 |
|---|---|---|
| **◎ 가 몰린 곳이 우리의 사업** | 관계(학부모·코치) + 검증 + 결산 | A 5개 · B 5개 · C 2개 = **12개** |
| **× 가 몰린 곳은 일부러 비운 곳** | 기존 도구가 더 잘하는 영역 | D 구역 3개 (일정·중계·결제) |
| **△ 는 "지금은 어렵다"는 정직한 표시** | 로드맵 또는 규제·비용 제약 | 진학 프로필, 공식 기록 연동 |

### 0-4. 우리가 비우는 4개 영역과 이유

| 비우는 기능 | 왜 비우는가 | 대신 어떻게 하는가 |
|---|---|---|
| **팀 일정·출석** | TeamSnap·CRM이 이미 표준. 따라 만들면 "또 하나의 팀 앱"이 됨 | 기존 도구 유지 + 우리는 **성장 기록만** |
| **경기 라이브 중계·영상** | 서버·트래픽 비용이 크고, Hudl·GameChanger가 압도적 | 영상은 **링크 연동**, 우리는 수치·서사 |
| **출석·수강료 결제** | 전자상거래·정산·환불 리스크. CRM의 핵심 영역 | 기존 CRM 병행, 필요 시 **제휴** |
| **공식 대회 기록** | 협회·공공 권한 영역. 민간이 대체 불가 | **입력 템플릿 + 검증 표시**로 보완 |

### 0-5. 한 줄 결론

> **"20개 중 12개는 우리만 할 수 있고, 3개는 일부러 하지 않는다."**
> 경쟁사와 같은 기능을 늘리는 것이 아니라, **아무도 하지 않는 12개를 먼저 완성**하는 것이 전략이다.
