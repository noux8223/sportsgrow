# Sports Grow 프로토타입 보완·수정 분석

기준일: 2026-11-16  
대상: 저장소 루트의 정적 웹 프로토타입 (`index.html`, 역할별 대시보드, `js/`, `css/`, `sw.js`)  
성격: 클릭해서 둘러보는 데모. 서버, 계정 체계, 결제, 종목 지표 엔진은 아직 없다.

이 문서는 화면을 더 예쁘게 만드는 제안이 아니라, **시연 신뢰도를 떨어뜨리는 불일치**, **그대로 배포하면 문제가 되는 경계**, **사업계획서의 MVP와 코드 사이의 빈칸**을 고칠 순서로 적는다.

현재 코드 규모는 앱 화면·스크립트·스타일 약 2.6만 줄이다. 학생 화면 `js/student.js` 1,993줄, 운영 콘솔 `js/admin.js` 2,095줄, 대시보드 스타일 `css/app.css` 4,363줄이 각각 한 파일에 모여 있다.

## 이미 동작하는 것

역할별 화면, 해시 기반 화면 전환, 학부모 코치 요청(`sportsgrow.parent.requests.v1`을 학생 화면과 코치 화면이 공유), 갤러리 업로드·본인 글 삭제, 공개 범위 값 저장, 관리자 콘솔의 필터·CSV·활동 로그, PWA 설치·오프라인 폴백·업데이트 안내, 로그인 탭과 모달의 키보드 처리까지는 데모로서 갖춰져 있다. 아래 항목은 그 위에 얹힌 빈칸과 오류다.

## 1. 우선순위

| 순위 | 묶음 | 이유 | 손대는 곳 |
| --- | --- | --- | --- |
| P0 | 같은 선수의 숫자가 화면마다 다름 | 시연 중 “훈련 추가 → 코치/기관/관리자 반영”이 성립하지 않음 | `js/student.js`, `js/coach.js`, `js/academy.js`, `js/admin.js` |
| P0 | 카드·피드·그래프가 입력과 분리된 채 고정 | 기록을 바꿔도 타율, 목표, 성장 곡선, 성장 피드가 그대로임 | `student.html`, `js/student.js` |
| P1 | 권한은 숨김·토스트 수준 | 읽기 전용 역할에 삭제 버튼이 보이고, 공개 범위가 화면을 가리지 않음 | `js/student.js`, `css/app.css` |
| P1 | 로그인 `next` 목적지 검증 | `http`로 시작하지 않는 주소는 그대로 이동 | `js/auth.js` |
| P1 | 데모를 외부에 올릴 때 필요한 경계 | 비밀번호·세션·약관·미성년자 데이터가 브라우저 안에만 있음 | `js/auth.js`, `index.html`, 신규 페이지 |
| P2 | MVP 기능 공백 | 초대, 주간 리포트, 알림, 결제, 지표 계산, 다계정 | 신규 모듈. 지금은 화면만 있음 |
| P2 | 구조·품질 장치 | 중복 헬퍼, 테스트 없음, 캐시 버전 수동 관리 | `js/*`, `sw.js`, 저장소 설정 |
| P3 | 문서가 코드를 따라가지 못함 | 진행정도 표와 README 폴더명이 현재 트리와 다름 | `docs/사업-앱-개발-진행정도-표.md`, `README.md` |

P0는 프로토타입을 투자·파트너 시연에 쓰기 전에 고친다. P1은 공개 URL에 올리기 전에 고친다. P2는 사업계획서의 M2–M3(계정·기록·통계·리포트)에 해당한다. P3는 제출 문서를 고칠 때 함께 맞춘다.

## 2. 데이터가 네 벌이다

한 선수 이야기가 네 개의 저장소에 따로 적혀 있다. 브라우저를 하나 써도 서로 갱신되지 않는다.

| 저장 키 | 쓰는 화면 | 김하람을 어떻게 아는가 |
| --- | --- | --- |
| `sportsgrow.player.training.v1`, `games`, `profile`, `visibility`, `media`, `gallery`, `cheers` | `student.html` | 훈련은 날짜 오프셋으로 생성. 오늘 기록은 타격 35분 |
| `sportsgrow.coach.*`, `sportsgrow.parent.requests.v1` | `coach.html` (+ 요청만 학생 화면과 공유) | 주간 훈련 350분, 목표 78%, 마지막 활동 “오늘 · 타격 35분”이 코드에 고정 (`js/coach.js` 시드) |
| `sportsgrow.academy.teams.v1` | `academy.html` | 팀 인원수만큼 이름·참여율·목표를 난수로 생성. 김하람 레코드가 없다 |
| `sportsgrow.admin.members.v1` 외 | `admin.html` | 김하람을 별도 회원으로 심음. 세션 42회, 출석 94%, 성장 지수 87 (`js/admin.js` 시드) |

학생 화면의 이번 주 시드(오프셋 0–6일)를 더하면 **320분**이다. 코치 카드는 **350분**이다. 관리자 성장 지수는 **87**이고, 학생 카드의 목표 달성률은 **78**로 박혀 있다. 같은 이름인데 같은 원장이 아니다.

학부모 요청만 예외다. `js/student.js`와 `js/coach.js`가 `sportsgrow.parent.requests.v1`을 같이 읽고 쓴다. 갤러리·훈련·응원도 학생 페이지 키를 쓰므로, 코치가 `student.html#media`로 들어오면 그 화면 안에서는 같이 보인다. 코치 대시보드의 선수 목록·목표·메모는 그 키를 읽지 않는다.

### 고칠 방향

1. 데모 원장을 한 덩어리로 둔다. 예: `sportsgrow.demo.v1` = 선수, 보호자 연결, 팀, 훈련, 경기, 목표, 메모, 요청, 갤러리.
2. 학생·코치·아카데미·관리자 화면은 그 원장을 역할에 맞게 잘라 보여 준다.
3. 김하람은 아카데미 명단과 관리자 회원 목록에 **같은 id**로 들어간다. 코치 화면의 주간 분은 학생 훈련 합계와 같게 계산한다.
4. 키를 역할마다 나누는 현재 구조는 “여러 학생”으로 확장할 때도 막힌다. 훈련 키가 `player.training` 하나라서 계정이 늘면 기록이 덮인다.

관리자 설정의 `데모 데이터 초기화`는 `js/admin.js`의 `KEYS`만 지운다. 학생·코치·아카데미 키는 남는다. 시연 초기화는 데모 원장 전체를 지우는 한 동작으로 모은다.

## 3. 입력해도 안 바뀌는 숫자

훈련 추가·삭제는 주간 분, 막대 차트, 훈련 목록, 강도 도넛까지는 다시 그린다 (`renderStats`, `renderOverviewChart`, `renderTraining`). 그 옆 카드와 피드는 초기 HTML·상수 그대로다.

### 3.1 학생 홈 KPI가 서로 모순된다

`student.html` 홈 카드:

- 이번 주 훈련량: JS가 `[data-stat-week]`만 갱신. 하단 `+12%`, `지난주 285분`은 고정 문구.
- 주간 훈련 목표: JS는 `[data-stat-week-count]`에 **최근 7일 기록 건수**를 넣는다. 시드는 7건이다. 화면 문구는 `7 / 5회`, 이어서 `목표 달성까지 1회 남음`이다. 건수와 남은 횟수가 같이 움직이지 않고, “회”와 “기록 건수”도 다르다. 같은 날 기록이 두 줄이면 횟수가 더 올라간다.
- 시즌 타율 `.312`, `최근 10경기 ▲ .024`: 경기 배열과 무관한 고정 문구.
- 목표 달성률 `[data-stat-goal]` 78: `renderStats`가 이 값을 쓰지 않는다. 훈련·경기를 바꿔도 78이다.

같은 화면의 목표 패널은 `2026년 10월 기준`, 주 4회 100%, 10월 타율 .320 88%, 시즌 30안타 72%로 고정이다. 카드는 주 5회를 말하고 패널은 주 4회를 말한다.

성장 곡선 `GROWTH` (`js/student.js`)는 5–10월 타율·출루율 배열이다. 경기를 추가해도 곡선이 다시 계산되지 않는다. 기준일이 2026-11-16이므로 곡선은 지난달에서 멈춘 채로 보인다.

### 3.2 오늘 훈련이 세 문장으로 적혀 있다

시드 오늘 기록 (`js/student.js` `seedTraining` 오프셋 0):

- 종류 타격, **35분**, 메모 `타격 120구 · 수비 40분`

성장 피드 첫 글 (`FEED_POSTS`):

- 제목 `오늘 타격 훈련 90분을 마쳤습니다`
- 날짜는 `daysAgo(0)`이라 오늘로 보임
- 본문·메타는 120구·수비 40분

코치 시드:

- 마지막 활동 `오늘 · 타격 35분`
- 주간 분은 350

피드 두 번째 글은 `daysAgo(3)`(2026-11-13)인데, 본문은 시드 경기 `2026-10-26 vs ○○중학교 · 4타수 3안타`와 같다. 경기 표의 날짜와 피드 날짜가 어긋난다.

### 3.3 경기 입력 필드가 화면보다 적다

`initGameForm`이 저장하는 필드는 날짜, 대회, 상대, 결과, 성과뿐이다. `score`는 빈 문자열, `achieved`는 항상 `false`, `id`가 없다.

- 최근 경기 카드는 `game.score`가 비어도 `" · " + score + " " + result`를 이어 붙인다. 새 기록은 `vs 상대 ·  승`처럼 빈 점수가 남는다.
- 표의 달성 열은 새 기록이 항상 `—`이다.
- 수정·삭제가 없다. 훈련만 삭제할 수 있다.
- 타율·출루율·OPS를 나눌 입력(타수, 안타, 볼넷)이 없다. 성과는 한 줄 텍스트다.

### 3.4 기간이 코드 안에 멈춰 있다

훈련 시드는 “오늘부터 N일 전”이라 달력이 바뀌어도 따라온다. 아래는 절대 날짜다.

- 경기 5건이 모두 `2026-10-12`–`2026-10-26`
- 성장 곡선 라벨이 5–10월
- 목표 패널 제목이 `2026년 10월 기준`
- 코치 목표 마감 `2026.10.31`은 기준일 이전에 끝남. 장기 마감 `2026.11.30`만 남아 있다
- 피드 본문의 `10월 타율 .320`

시연 날짜와 데이터 날짜를 맞추려면, 경기·목표·피드도 훈련처럼 기준일 오프셋으로 만들거나, 화면의 “기준 월”을 데이터에서 읽어야 한다.

### 고칠 방향

- 홈의 네 카드, 목표 바, 성장 곡선, 성장 피드를 저장값에서 계산한다.
- 주간 목표는 한 숫자로 정한다. “이번 주 기록한 날 수 / 목표 횟수”, 남은 횟수는 `max(0, 목표 - 달성)`으로 그린다. 지난주 대비 증감도 지난 7일과 그 이전 7일을 비교해 계산한다.
- 경기 폼에 점수와 성과 수치를 넣고, 행마다 id를 부여해 수정·삭제를 연다.
- 피드는 훈련·경기·목표 이벤트에서 만든다. 문구용 배열을 따로 두지 않는다.
- `writeStore` 실패를 훈련·경기 저장에서도 알린다. 프로필·갤러리는 용량 부족 토스트가 있고, 훈련 저장(`initTrainingForm`)은 반환값을 보지 않는다. 사진·동영상을 `localStorage`에 넣으면 할당량이 먼저 찬다.

## 4. 권한·화면 동작

역할 가드는 `document.body[data-role]`과 `localStorage` 세션을 비교한다 (`js/auth.js` `guard`). 학생 페이지는 `player`, `parent`, `coach`를 허용한다. 학부모·코치에는 `is-readonly`가 붙고, 기록 저장 함수가 역할이 학생이 아니면 토스트 후 반환한다.

이 가드는 화면을 연 뒤 `DOMContentLoaded`에서 실행된다. `student.js`는 `defer` 시점에 먼저 실행되며, 세션이 없으면 역할을 `player`로 둔 채 시드를 쓰고 화면을 그린다. 로그인하지 않은 방문에도 학생 기록이 저장되고, 리다이렉트 전에 학생 화면이 한 번 보인다.

### 4.1 읽기 전용인데 삭제 버튼이 있다

훈련 목록은 `trainingRow(item, true)`로 삭제 버튼을 항상 만든다. CSS는 `[data-player-only]`, `[data-parent-only]`만 숨긴다 (`css/app.css`). 삭제 버튼에는 그 속성이 없다. 학부모·코치가 누르면 JS가 “학생 계정에서만 삭제할 수 있습니다”를 띄운다. 버튼을 만들지 않는 쪽이 맞다.

### 4.2 공개 범위가 저장만 된다

`initVisibility`는 `profile` / `training` / `games` / `goals`를 `비공개·팀·전체`로 저장하고, 학생만 수정하게 막는다. 저장된 값으로 섹션을 숨기거나 코치·학부모·외부 카드에서 필드를 빼는 코드는 없다. 프로필 안내 문구는 “활동 이력은 공개 범위 설정에 따라 코치와 학부모에게만 표시됩니다”라고 되어 있다. 학부모·코치로 `student.html`에 들어가면 비공개 목표까지 같은 화면이 열린다.

사업계획서의 공개 단계는 비공개·초대·전체이고, 화면 선택지는 비공개·팀 공개·전체 공개다. 이름부터 맞춘다.

### 4.3 알림은 고정 문구다

학생 `notificationsBtn`은 클릭 시 `새 알림 2건 · 코치 피드백 1건, 주간 목표 달성 1건`만 보여 준다. `aria-label`도 `알림 2건`으로 고정이다. 코치·아카데미도 같은 패턴이고 건수가 3으로 적혀 있다. 코치 요청을 처리해도 배지가 줄지 않는다.

### 4.4 운영 설정이 사이트로 나가지 않는다

관리자 설정의 가입 승인, 점검 모드, 서비스 이름, 입금 마감일은 `sportsgrow.admin.settings.v1`에만 저장된다. `index.html`과 `login.html`은 이 키를 읽지 않는다. 점검 모드를 켜도 랜딩과 로그인은 그대로다.

### 4.5 비밀번호 보기 아이콘이 바뀌지 않는다

`js/auth.js` 비밀번호 토글은 입력 타입과 `aria-label`은 바꾸지만, 아이콘 `href`는 보이는 상태와 숨긴 상태 모두 `#i-eye`다.

```javascript
if (use) use.setAttribute("href", show ? "#i-eye" : "#i-eye");
```

감춤 상태에는 다른 심볼을 쓴다. 스프라이트에 눈 가림 아이콘이 없으면 추가한다.

### 고칠 방향

- 가드를 데이터 로드보다 앞에 둔다. 세션이 없거나 역할이 아니면 시드를 쓰지 않고 로그인으로 보낸다.
- 역할별로 “읽을 수 있는 필드 / 쓸 수 있는 동작” 표를 한 모듈에 두고, 버튼 생성과 저장이 그 표를 같이 본다.
- 공개 범위 `private`는 해당 역할 화면에 빈 상태 문구를 보여 준다. `team`은 코치·학부모, `public`은 그 외 열람(데모에서는 아직 공개 프로필 URL이 없으므로, 만들기 전까지 배지만 전체 공개로 두지 말고 열람 규칙을 주석이 아닌 코드로 둔다).

## 5. 공개 전에 막을 경계

이 저장소는 데모다. 아래는 데모에서 허용해도, 주소가 공개되거나 실명·실사진이 들어가는 순간 고쳐야 하는 항목이다.

### 5.1 로그인 이동 주소

`js/auth.js`는 쿼리 `next`가 `http`로 시작하지 않으면 그 문자열로 이동한다.

```javascript
var destination = nextPage && nextPage.indexOf("http") !== 0 ? nextPage : role.page;
```

`https://`는 막힌다. `//다른사이트`, `javascript:` 형태는 `http`로 시작하지 않아 통과한다. 허용 목록은 역할별 페이지 파일명으로 한정한다. `student.html`, `coach.html`, `academy.html`, `admin.html` 중 해당 역할이 열 수 있는 것만 남긴다.

### 5.2 인증이 브라우저 저장값이다

계정과 비밀번호 `grow1234`가 `js/auth.js`의 `ROLES`에 있다. 세션은 `sportsgrow.session.v1`에 역할·이메일·이름을 넣고 만료가 없다. 개발자 도구에서 역할을 `admin`으로 바꾸면 운영 콘솔 가드를 통과한다. 데모 안내 문구와 README에 이미 적혀 있으므로 시연용으로는 분명하다. 공개 서버에 이 파일을 그대로 두면 운영 화면이 같이 열린다.

공개 배포 최소 조건:

- 운영 계정·데모 비밀번호를 소스에서 제거
- 세션은 서버가 발급한 만료 있는 쿠키
- 역할 검사는 API에서 다시 수행
- `admin-login.html`은 공개 푸터 링크 대신 별도 경로·망 제한

### 5.3 이용약관·개인정보처리방침 페이지가 없다

푸터는 문장만 있다 (`index.html` `이용약관 · 개인정보처리방침`). 링크가 아니다. `#safety` 섹션은 원칙 소개다. 만 14세 미만 선수 기록을 다루는 서비스의 제출·파일럿 전에는 약관, 처리방침, 보호자 동의, 열람·삭제·정정 요청 경로가 실제 문서로 있어야 한다. 관리자 시드에는 `010-2841-7732` 형태의 전화번호가 들어 있다. 가공 번호라도 미성년 선수 화면의 기본 데이터에서는 전화번호를 빼는 편이 안전하다.

### 5.4 저장값 XSS

응원, 갤러리 설명, 코치 메모, 관리자 표는 이스케이프 후 `innerHTML`에 넣는다. 학생 화면의 훈련 종류, 기록 id, 경기 `result`, 최근 카드의 `score`는 이스케이프하지 않는다. 입력 폼의 선택값만 저장되는 동안은 안전하다. `localStorage`를 고치면 그대로 HTML이 된다. 공유 PC 데모에서는 저장값을 신뢰하지 말고, 학생 화면에도 코치 화면과 같은 `esc`를 모든 삽입 문자열에 적용한다.

갤러리·히어로 미디어는 `data:image`, `data:video`, `images/`만 허용한다. 이 검사는 유지한다.

### 5.5 외부 폰트

전 페이지가 `cdn.jsdelivr.net`의 Pretendard를 로드한다. 서비스 워커는 그 호스트를 런타임 캐시 `sportsgrow-runtime-v1`에 넣으며, 이 캐시 이름은 버전을 올리지 않는다. 첫 방문이 CDN 장애와 겹치면 글꼴이 빠진다. 정적 파일로 포함하고, 스타일시트에 SRI 또는 자체 호스팅을 건다.

다국어, 일본·중국 진입에 필요한 문구 분리는 시작되지 않았다. 문자열은 HTML과 JS에 한국어로 박혀 있다. Wave 1 현지화 전에 카피 추출이 필요하다. 지금 당장의 시연 범위는 아니다.

## 7. 구조와 품질 장치

### 7.1 같은 함수가 파일마다 있다

날짜 포맷, `daysAgo`, HTML 이스케이프가 `student.js`, `coach.js`, `academy.js`, `admin.js`에 각각 있다. 저장 헬퍼는 `app-shell.js`에 있고, 세션 저장은 `auth.js`에 따로 있다. 이스케이프 누락(3.2, 5.4)이 이 중복에서 나왔다. 공통 모듈 하나로 모으면 P0 수정 때 계산식도 한곳에 둘 수 있다.

빌드 도구는 없다. README의 실행 방법은 `python -m http.server`다. 프레임워크 도입 여부와 무관하게, 다음 회귀는 지금 구조에서 막는다.

- 김하람 주간 분: 학생 카드 = 코치 카드 = 원장 합계
- 학부모·코치 세션에서 훈련 삭제 버튼이 없음
- 공개 범위 `private`인 목표가 학부모 화면에 없음
- `next`에 `https://`, `//`, `javascript:`를 넣으면 역할 기본 페이지로만 이동
- 경기 한 건 추가 시 최근 카드에 빈 점수가 없음

테스트 러너, 린트, CI 설정 파일이 저장소에 없다. 위 다섯은 브라우저에서 손으로 확인 가능한 시나리오다. 자동화는 M6 QA 항목과 맞물린다.

### 7.2 서비스 워커

`sw.js`의 `VERSION`은 `sportsgrow-v11`이고, README가 말하듯 배포마다 사람이 올려야 한다. 정적 자산은 stale-while-revalidate라서, 버전을 올리지 않으면 이전 JS가 먼저 보인다. `install`의 `cache.addAll`은 프리캐시 목록 중 하나라도 실패하면 설치 전체가 실패한다.

프리캐시에 `mockup.html`, `css/mockup.css`, `images/cover/`는 없다. 앱 화면은 커버 이미지를 쓰지 않아 당장의 오프라인 공백은 작다. 랜딩이 커버를 쓰기 시작하면 목록에 넣는다.

오프라인에서 훈련 입력은 큐에 쌓이지 않는다. 계획서의 성능 목표(입력 30초, 오프라인 작성)를 말하려면 실패 시 재시도 큐가 필요하다. 지금은 온라인 데모로 한정해 설명하는 것이 정확하다.

### 7.3 접근성·화면

로그인, 모달 포커스 이동, 사이드바 `aria-expanded`, 스킵 링크, 뷰 라우터 `aria-current`는 들어가 있다. 이어서 볼 곳:

- 알림 버튼의 접근 이름에 고정 건수가 들어 있다.
- 관리자·로그인 CSS에 9px–10.5px 텍스트가 있다. 표 보조 문구는 12px 이상으로 올린다.
- 본문 `word-break: keep-all`은 한국어에 맞다. 좁은 화면에서 긴 대회명이 넘치면 해당 셀만 줄바꿈을 허용한다.
- 모달 포커스 트랩은 포커스가 모달 안에 있을 때 `Tab`을 가둔다. 열릴 때 첫 필드로 포커스를 보내는 코드가 있어 기본 경로는 동작한다. 드로어(코치 선수, 아카데미 팀)에는 같은 트랩이 없다.

### 7.4 README와 폴더명

`README.md` 폴더 구조 주석의 루트 이름이 `baseball-grow/`다. 실제 디렉터리는 `sportsgrow`다. 학부모 설명은 앞부분에서 “읽기 전용 열람·응원·코치 요청”으로 요약되고, 갤러리 표에서는 업로드·댓글이 허용된다. 구현은 갤러리 표가 맞다. 요약 문장을 표와 같게 고친다.

`_legacy/`는 이전 야구 단일 사이트로, 현재 서비스 워커와 링크에 포함되지 않는다. 보존 목적이 끝나면 저장소 밖으로 옮긴다. 시연 중 이전 화면이 열리는 경로는 없다.

## 9. 손대는 순서

한 번에 서버로 옮기지 않는다. 시연 원장을 먼저 하나로 만들고, 그 다음 빈 기능을 채운다.

1. **원장 통합**  
   김하람, 이정은, 박정우, 한빛 아카데미를 한 JSON으로 정의한다. 학생 훈련 합계가 코치 카드와 관리자 회원 행에 같게 나오게 한다. 아카데미 명단에 같은 선수 id를 넣는다.

2. **파생 수치 제거**  
   홈 KPI, 목표 바, 성장 곡선, 성장 피드를 원장에서 계산한다. 10월 고정 문구와 절대 날짜 시드를 기준일 기준으로 바꾼다. 주간 목표 횟수를 4회 또는 5회 중 하나로 정한다.

3. **경기 입력**  
   점수·수치 성과·id·삭제. 최근 카드의 빈 점수 문자열을 없앤다. 저장 실패 토스트를 훈련·경기에 추가한다.

4. **권한**  
   가드를 시드보다 앞으로. 읽기 전용 역할에서 삭제 버튼 제거. 공개 범위가 섹션 표시를 바꾸게. 비밀번호 아이콘 수정. `next` 허용 목록.

5. **시연 초기화**  
   학생·코치·아카데미·관리자 키를 한 버튼으로 지운다.

6. **문서**  
   README 경로·권한 요약, 진행정도 표의 화면 범위. 사업계획서의 “랜딩·로그인만 구축” 문장.

7. **MVP로 넘어갈 때**  
   서버 계정, 보호자 초대, 주간 리포트, 야구 지표 계산, 알림. 결제·OCR·다국어는 그 뒤에 둔다. 공개 URL을 만들기 전에 5장의 비밀번호·약관·전화번호 시드를 처리한다.

이 순서의 1–6은 현재 정적 사이트 안에서 끝난다. 7부터 저장소 구조가 바뀐다.
