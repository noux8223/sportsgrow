Q1
기술 형태

12개월 안에 카메라 OCR·음성 자동 입력이 필수인가?

NOPWA·웹앱 우선. 설치 없이 시작하고 개발비를 줄인다.
YES크로스플랫폼(React Native·Flutter) 또는 네이티브 검토.
A
아니오. OCR·음성은 M10~으로 이연 → PWA 우선, 카메라·푸시는 필요 시 네이티브 브리지로 보완.
Q2
입력 환경

훈련장·체육관에서 오프라인 기록이 필요한가?

YES로컬 DB + 동기화 큐 + 충돌 해결 규칙을 먼저 설계.
NO서버 API 우선. 단순한 구조로 시작.
A
예. 입력이 끊기면 3일 안에 이탈한다 → 오프라인 우선, 재접속 시 자동 동기화·중복 방지.
Q3
수익·결제

학부모 구독 결제가 앱 안에서 발생하는가?

YES스토어 IAP, 수수료 15~30%, 구독 복원·환불 정책 필수.
NO웹 결제 + 앱은 열람 전용. B2B는 세금계산서.
A
B2C는 앱 내 결제 가능성 → IAP vs 외부 결제 비교. B2B(코치·아카데미)는 웹 계약·세금계산서로 분리.
Q4
데이터·동의

미성년자 개인정보를 저장하는가?

YES법정대리인 동의, 권한 매트릭스, 국내 리전, 암호화, 파기.
NO일반 개인정보 보호 수준 적용.
A
예(필수). 설계 단계부터 PIA·동의·공개 범위를 넣는다. 사후 추가는 재작업 비용이 가장 크다.
Q5
성능·접근성

저사양 기기·저속 네트워크 사용자가 있는가?

YES경량 번들, 이미지 지연 로딩, 오프라인 캐시, 배터리 고려.
NO기본 성능 목표만 설정.
A
예. 전국 아카데미·학부모 → 저가 Android·3G 기준으로 앱 크기와 첫 화면 속도를 맞춘다.
Q6
스토어 정책

아동·청소년 대상 앱으로 심사되는가?

YES아동 대상 정책, 광고·추적 제한, 개인정보 라벨, 보호자 동의.
NO일반 심사 기준 적용.
A
가능성 높음. 만 14세 미만 보호자 동의, 광고 없음, 데이터 판매 없음. 스토어 개인정보 라벨을 실제 수집과 일치.
Q7
출시·운영

출시 후 운영·롤백 체계가 있는가?

YES단계적 배포, 크래시·ANR, 푸시, 버전 정책, CS, 롤백.
NO출시 보류. 파일럿으로 되돌린다.
A
파일럿 3곳 → 1곳 유료 후 단계 배포 — 유료 전환은 M3, 전체 공개는 지표 확인 후(M9).

  • 한 기기에서 학부모/코치 계정 전환
  • 초대 링크·딥링크·가입 없는 열람

  • 공개 범위(비공개·코치·학부모·전체)
